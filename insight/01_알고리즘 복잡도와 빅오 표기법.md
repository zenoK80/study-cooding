# 01. 알고리즘 복잡도와 빅오 표기법

## 뜻

- **시간 복잡도**: 데이터가 늘 때 작업량이 얼마나 늘어나는지.
- **공간 복잡도**: 데이터가 늘 때 필요한 메모리가 얼마나 늘어나는지.
- **빅오(Big O)**: 증가 정도를 `O(n)`처럼 표현하는 표기법. 실제 실행 시간(초)이 아닙니다.
- **n**: 입력 개수. 완주하지 못한 선수 문제에서는 참가자 수입니다.

## 자주 보는 표기

- `O(1)`: 입력이 늘어도 작업량이 일정. 예: 배열의 첫 원소 조회.
- `O(log n)`: 탐색 범위를 절반씩 줄이는 방식. 예: 이진 탐색에서 1,024개를 약 10단계로 좁히기.
- `O(n)`: 입력이 2배면 작업량도 대략 2배. 예: 배열 전체 순회.
- `O(n log n)`: n에 log n을 곱한 만큼 증가. 예: 일반적인 효율적 정렬.
- `O(n²)`: 입력이 2배면 작업량은 대략 4배. 예: 원소마다 전체 배열을 다시 검색.
- 입력이 충분히 클 때 증가 정도는 보통 `O(1) < O(log n) < O(n) < O(n log n) < O(n²)` 순입니다.

## 코드에서 어떻게 판단하나?

반복문 개수가 아니라 **총 작업 횟수**를 봅니다. 아래 본문 작업은 한 번에 일정한 시간이 든다고 가정합니다.

```javascript
for (let i = 0; i < n; i++) { /* 작업 */ }
// n번 → O(n)
```

```javascript
for (let i = 0; i < n; i++) { /* 작업 */ }
for (let i = 0; i < n; i++) { /* 작업 */ }
// n + n = 2n번 → O(n): 고정 배수 2는 생략
```

```javascript
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) { /* 작업 */ }
}
// n × n번 → O(n²)
```

- `indexOf()`·`filter()` 같은 메서드 내부의 탐색도 포함합니다. 한 줄이라고 작업 한 번은 아닙니다.
- 반복문이 중첩돼도 범위에 따라 복잡도는 달라집니다. 무조건 `O(n²)`은 아닙니다.

## 추가 공간은 무엇인가?

입력으로 받은 데이터 외에 **새로 사용하는 메모리**입니다. 변수 개수가 아니라 저장하는 데이터 크기를 봅니다.

```javascript
let count = 0;                    // 숫자 하나 → O(1)
const copy = [...participant];    // n개를 복사 → O(n)
const counts = new Map();         // 빈 Map 생성 후, 무엇을 얼마나 저장하느냐에 따라 달라짐
```

- 이름 종류가 u개면 이름별 인원수를 저장한 Map은 `O(u)` 공간을 사용합니다.
- 모두 다른 이름이면 `u = n`이므로 `O(n)`, 모두 같은 이름이면 항목 하나입니다.

## 지금 문제에 적용

- **객체·Map 집계**: 참가자 더하기 → 완주자 빼기 → 남은 이름 찾기. 일반적인 해시 구현에서 평균 시간 `O(n)`, 최악의 추가 공간 `O(n)`.
- **정렬 비교**: 일반적인 정렬 기준 시간 `O(n log n)`. 복사본을 만들면 복사 배열에 추가 공간 `O(n)`이 필요합니다. 정렬 내부 비용은 구현에 따라 다릅니다.
- **찾아서 하나씩 삭제**: 반복 검색과 배열 이동 때문에 최악의 시간 `O(n²)`.

## 주의

- **평균**은 가정한 입력·동작의 평균적인 비용, **최악**은 가장 불리한 경우의 비용입니다. 빅오 자체가 무조건 최악을 뜻하지는 않습니다.
- **통상**은 공식 용어가 아니라 ‘일반적으로’라는 뜻입니다.
- 복잡도가 좋다고 모든 입력에서 실제 실행 시간이 더 짧지는 않습니다. 실제 속도는 별도로 측정합니다.
