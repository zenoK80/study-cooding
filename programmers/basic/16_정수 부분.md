# 16. 정수 부분

[프로그래머스 원문](https://school.programmers.co.kr/learn/courses/30/lessons/181850?language=javascript)

- 분류: 코딩 기초 트레이닝 · 함수(메서드) · Lv. 0
- 상태: [x] 풀이 완료

## 문제 설명

실수 `flo`가 매개변수로 주어질 때, `flo`의 정수 부분을 return하도록 solution 함수를 완성해주세요.

## 제한사항

- 0 ≤ `flo` ≤ 100

## 입출력 예

| flo | result |
| ---: | ---: |
| 1.42 | 1 |
| 69.32 | 69 |

## 입출력 예 설명

- 예제 #1: 1.42의 정수 부분은 1입니다.
- 예제 #2: 69.32의 정수 부분은 69입니다.

## 문제 코드

```javascript
function solution(flo) {
  var answer = 0;
  return answer;
}
```

## 나의 풀이

```javascript
const solution = (flo) => Math.trunc(flo);
```

정답입니다. 소수점 아래를 버리고 정수 부분만 남깁니다. 1.99도 반올림하지 않고 1을 반환합니다.

## 다른 방법

### (1) Math.floor — 이 문제의 범위에서는 같은 결과

```javascript
const solution = (flo) => Math.floor(flo);
```

flo가 0 이상이므로 trunc와 결과가 같습니다. 음수가 허용되는 다른 문제에서는 둘을 구분해야 합니다.

### (2) 일반 함수 + return — 같은 동작을 풀어 쓰기

```javascript
function solution(flo) {
  return Math.trunc(flo);
}
```

화살표 함수 대신 일반 함수로 작성한 형태입니다. 계산 방법은 같습니다.

### (3) ~~ — 비트 연산 공부용

```javascript
const solution = flo => ~~flo;
```

이 문제의 0~100 범위에서는 정답입니다. 다만 일반적인 소수 부분 버리기에는 Math.trunc를 추천합니다. 큰 수에서는 결과가 달라집니다. 매개변수가 하나라 `(flo)`의 괄호도 생략한 형태입니다.

## 배울 것들

### 이번에 헷갈린 부분

- `(flo)`: 함수를 호출할 때 전달한 값을 받는 매개변수입니다. `solution(1.42)`로 호출하면 flo에 1.42가 들어옵니다.
- `() => Math.trunc(flo)`처럼 매개변수를 빼면 전달한 값을 flo로 받지 못합니다. 바깥에도 flo가 선언되어 있지 않으면 ReferenceError가 발생합니다.
- 정확한 철자는 `trunc`입니다. `Math.turnc()`는 없는 메서드라 호출하면 TypeError가 발생합니다.
- `=> Math.trunc(flo)`는 표현식의 결과를 자동 반환합니다. 중괄호를 쓰면 `=> {return Math.trunc(flo);}`로 작성합니다.

### Math 메서드 4가지

| 메서드 | 정확한 뜻 | 1.42 | 1.99 | -1.42 | 2 |
| --- | --- | ---: | ---: | ---: | ---: |
| Math.trunc(x) | 소수 부분을 버려 0 방향으로 정수화 | 1 | 1 | -1 | 2 |
| Math.floor(x) | x 이하인 정수 중 가장 큰 값 | 1 | 1 | -2 | 2 |
| Math.ceil(x) | x 이상인 정수 중 가장 작은 값 | 2 | 2 | -1 | 2 |
| Math.round(x) | 가장 가까운 정수, 정확히 중간이면 큰 쪽 | 1 | 2 | -1 | 2 |

- `Math`는 수학 기능을 모아 둔 내장 객체입니다. `trunc`, `floor`, `ceil`, `round`는 그 객체에 붙은 **메서드**입니다.
- 사용법은 `Math.trunc(flo)`입니다. `flo.Math.trunc()`나 `flo.trunc()`가 아닙니다.
- 네 메서드는 모두 **숫자(Number)**를 반환합니다. 문자열로 바꾸는 기능이 아닙니다.
- 이미 정수이면 그대로입니다. 올림이라고 `Math.ceil(2)`가 3이 되는 것은 아닙니다.
- **정수 부분만 필요하면 trunc**, 아래쪽 정수면 floor, 위쪽 정수면 ceil, 가까운 정수면 round입니다.
- `Math.round(1.5)` → 2, `Math.round(-1.5)` → -1입니다. 음수의 정확한 중간값도 더 큰 수 쪽으로 갑니다.

### trunc와 floor — 음수에서 차이

- `Math.trunc(-1.42)` → -1: 소수 부분 .42만 버립니다.
- `Math.floor(-1.42)` → -2: -1.42보다 작거나 같은 정수 중 가장 가까운 값을 고릅니다.
- 숫자 크기는 `-2 < -1.42 < -1`입니다. **음수에서는 -2가 -1보다 작습니다.**
- 따라서 ‘소수 부분 버리기’와 ‘내림’은 항상 같은 말이 아닙니다. 이 문제는 **0을 포함한 0 이상의 값**만 주어져 결과가 같은 것입니다.

### toFixed()는 무엇이 다를까?

- 사용법: `숫자.toFixed(소수점 아래 자릿수)`.
- 지정한 자리까지 **반올림하고 문자열로 반환**하는 Number 메서드입니다. 정수 부분만 구하는 메서드가 아닙니다.
- `toFixed(0)`의 0은 ‘소수점 아래 0자리까지 표시’, 즉 정수 모양으로 표시한다는 뜻입니다.
- `toFixed(2)`는 소수점 아래 2자리까지 표시합니다. 부족하면 0을 채웁니다.

```javascript
(1.42).toFixed(0);    // '1' — 문자열
(1.99).toFixed(0);    // '2' — 버림이 아니라 반올림
(1.4).toFixed(2);     // '1.40' — 소수점 아래 2자리 표시
typeof (1.42).toFixed(0); // 'string'
typeof Math.trunc(1.42); // 'number'
```

**이 문제에 toFixed를 쓰면 안 맞는 이유는 두 가지입니다.**

- 자료형: 답은 숫자 1이어야 하는데 문자열 '1'을 반환합니다.
- 계산 방식: `1.99`의 정수 부분은 1인데 toFixed(0)은 '2'로 반올림합니다. `Number((1.99).toFixed(0))`처럼 숫자로 다시 바꿔도 2라 틀립니다.

toFixed는 화면에 금액·측정값 등을 일정한 소수 자릿수로 **표시**할 때 쓰면 됩니다. 다만 소수는 이진수로 정확하게 저장되지 않는 경우가 있어, `(2.55).toFixed(1)`처럼 예상과 다른 반올림 결과('2.5')가 나올 수 있습니다.

### Math.trunc(flo)와 flo.toFixed(0)의 호출 차이

- `Math.trunc(flo)`: Math 객체의 trunc 메서드에 flo를 **인자**로 전달합니다.
- `flo.toFixed(0)`: flo라는 **숫자 값의 메서드**를 호출하며, 0은 표시할 소수 자릿수입니다.
- 둘 다 메서드입니다. **어떤 객체·값에 붙어 있는 메서드인지**가 다른 것입니다.
- JavaScript에서는 `1.42`와 `1`이 모두 Number 자료형입니다. 여기서 ‘정수로 바꾼다’는 것은 자료형을 바꾸는 게 아니라 소수 부분이 없는 숫자 값을 만든다는 뜻입니다.

### ~~는 무슨 문법이야?

- `~`는 **비트 NOT 연산자**입니다. 함수나 메서드가 아니라 `+`, `-`처럼 연산자입니다.
- 비트는 0 또는 1을 담는 한 자리입니다. `~`는 각 자리를 `0 → 1`, `1 → 0`으로 뒤집습니다.
- `~~flo`라는 별도 연산자가 있는 게 아니라 **`~(~flo)`**, 즉 두 번 적용한 것입니다.
- `!`는 참·거짓을 뒤집는 논리 NOT이고, `~`는 숫자의 비트를 뒤집는 비트 NOT입니다. `!!flo`와 `~~flo`는 전혀 다릅니다.

### 원래 숫자는 몇 비트인데?

- JavaScript의 일반 숫자 **Number는 64비트 부동소수점 방식**으로 값을 표현합니다. 64비트 정수라는 뜻은 아닙니다. 소수와 큰 수를 표현하기 위해 부호·지수·유효숫자를 나눠 사용합니다.
- Number에 `~`를 적용할 때는 **먼저 부호 있는 32비트 정수로 변환한 다음** 비트를 뒤집습니다. 두 번 써야 32비트가 되는 게 아니라 첫 번째부터 변환합니다.
- ‘원래 64비트 중 절반을 그냥 잘라낸다’가 아닙니다. **숫자 값을 정수로 변환하는 과정**이며, 작은 유한한 숫자는 이때 소수 부분이 버려집니다.
- 연산 결과의 JavaScript 자료형은 여전히 Number입니다. `typeof ~~1.42` → `'number'`. 별도의 int 자료형으로 바뀌는 것은 아닙니다.
- 이 설명은 Number 기준입니다. **BigInt의 ~는 32비트로 제한하지 않습니다.** `~~123n`은 `123n`입니다. [MDN Number](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number), [MDN 비트 NOT](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Bitwise_NOT).

### 1.42가 왜 1이 되는지 순서대로

```javascript
const flo = 1.42;
const once = ~flo;   // 32비트 정수 1로 변환 → 뒤집어서 -2
const twice = ~once; // -2의 비트를 다시 뒤집어서 1
console.log(twice);  // 1
```

**소수가 사라진 이유는 ‘비트를 두 번 뒤집어서’가 아니라, 첫 연산 전에 정수로 변환했기 때문입니다.** 두 번 뒤집으면 정수의 비트만 복원되고, 이미 버린 .42는 돌아오지 않습니다.

### 왜 ~1은 -1이 아니라 -2야? — 2의 보수

- 컴퓨터는 정해진 비트 수 안에서 음수도 표현해야 합니다. 여기서는 **2의 보수**라는 표현 방식을 사용합니다.
- 양수에서 대응하는 음수를 만드는 방법은 **모든 비트를 뒤집고 1을 더하기**입니다. 뒤집기만 한 값은 ‘1의 보수’라고 부릅니다.
- 실제 연산은 32비트지만, 아래는 읽기 쉽게 **8비트로 축소한 예시**입니다.

```text
 +1: 00000001
 ~1: 11111110  → 2의 보수 방식으로 읽으면 -2
     11111111  → 여기에 1을 더해야 -1

 ~(-2): 00000001 → 다시 뒤집으면 +1
```

- 이 방식에서 8비트의 맨 왼쪽 자리는 값이 `-128`이고, 나머지 자리는 `64, 32, 16, 8, 4, 2, 1`입니다.
- 따라서 `11111110`은 `-128 + 64 + 32 + 16 + 8 + 4 + 2 = -2`입니다. 단순히 ‘맨 앞에 마이너스 표시를 붙인 126’이 아닙니다.
- 같은 원리로 **32비트 정수 x에 대해 `~x = -x - 1`**입니다. `~1 = -2`, `~(-2) = 1`입니다.
- `~`는 **뒤집기만** 합니다. ‘뒤집고 1을 더해서 음수로 만드는 연산’ 자체는 아닙니다. 음수 표현 방식과 연산 동작을 구분하면 됩니다.

### 왜 정답인데 추천하지 않아?

- Number의 ~~ 결과 범위는 **-2,147,483,648 ~ 2,147,483,647**입니다. 범위를 벗어나면 32비트 변환 과정에서 값이 달라집니다.
- 예를 들어 2,147,483,648은 32비트에서 맨 왼쪽 비트만 1입니다. 부호 있는 정수로 해석하면 -2,147,483,648이 됩니다.
- NaN·Infinity도 0으로 바뀌고, 음수 0도 보존하지 않습니다. 따라서 Math.trunc의 완전한 대체품은 아닙니다.

```javascript
~~1.99;                  // 1
~~(-1.99);               // -1 — floor의 -2와 다름
~~2147483648;            // -2147483648 — 큰 수에서 값이 달라짐
Math.trunc(2147483648);  // 2147483648
~~Infinity;              // 0
Math.trunc(Infinity);    // Infinity
!!1.42;                  // true — 논리 연산이므로 다른 결과
```

**기억할 한 문장: ~~는 ‘소수 버리기 전용 기능’이 아니라 ‘32비트 정수로 변환하고 두 번 뒤집기’입니다.** 짧다고 무조건 더 빠르다고 볼 수도 없습니다. [MDN도 정수 부분 추출에는 Math.trunc 사용을 권합니다.](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Bitwise_NOT)

## 시간·공간 복잡도 쉽게 보기

- **시간 O(1)**: Number 하나에 정해진 계산을 합니다. flo가 1.42든 99.99든 반복문으로 1부터 세지 않습니다.
- **추가 공간 O(1)**: 결과 숫자 하나만 반환합니다. 입력에 비례해 커지는 배열이나 문자열을 따로 만들지 않습니다.
- 위의 trunc·floor 풀이 모두 같습니다. 한 줄 화살표 함수로 줄이는 것은 성능 개선이 아니라 작성 방식의 차이입니다.
- Number에 적용한 ~~도 고정된 32비트를 다루므로 시간·추가 공간 O(1)입니다. 같은 빅오 표기라고 실제 실행 속도까지 같거나 ~~가 더 빠르다는 뜻은 아닙니다.

**가장 추천하는 풀이: 네 Math.trunc(flo) 풀이 — ‘소수 부분을 버리고 정수 부분만 남긴다’는 문제의 요구를 정확히 표현하며, 음수에서도 floor와 혼동할 필요가 없습니다.**
