## 문제 설명

`FIRST_HALF` 테이블은 아이스크림 가게의 상반기 주문 정보를 담은 테이블입니다. `SHIPMENT_ID`, `FLAVOR`, `TOTAL_ORDER`는 각각 아이스크림 공장에서 가게까지의 출하 번호, 아이스크림 맛, 상반기 아이스크림 총주문량을 나타냅니다.

| NAME | TYPE | NULLABLE |
| --- | --- | --- |
| SHIPMENT_ID | INT(N) | FALSE |
| FLAVOR | VARCHAR(N) | FALSE |
| TOTAL_ORDER | INT(N) | FALSE |

## 문제

상반기에 판매된 아이스크림의 맛을 **총주문량 기준 내림차순**으로 정렬하고, 총주문량이 같다면 **출하 번호 기준 오름차순**으로 정렬하여 조회하는 SQL 문을 작성해주세요.

## 예시 설명

- 주문량 3200인 chocolate, 3150인 melon이 먼저 나옵니다.
- 3100인 두 맛은 출하 번호 105인 white_chocolate → 109인 strawberry 순서입니다.
- 2900인 세 맛은 출하 번호 108인 mango → 111인 orange → 112인 pineapple 순서입니다.
- 나머지도 주문량이 많은 순서대로 출력합니다. 최종 결과에는 맛 컬럼만 표시합니다.

## 나의 풀이

```sql
SELECT FLAVOR
FROM FIRST_HALF
ORDER BY TOTAL_ORDER DESC, SHIPMENT_ID ASC;
```

## 다른 방법

### (1) ASC 생략 — 기본 정렬 방향 활용

```sql
SELECT FLAVOR
FROM FIRST_HALF
ORDER BY TOTAL_ORDER DESC, SHIPMENT_ID;
```

정렬 방향을 생략하면 ASC라서 결과는 같습니다. 공부할 때는 네 답처럼 두 방향을 모두 적는 편이 명확합니다.

## 배울 것들

### SELECT 뒤에는 컬럼, FROM 뒤에는 테이블?

- `SELECT FLAVOR`: **결과에 보여 줄 열**을 지정합니다. 여기서는 맛만 출력합니다.
- 여러 열을 보려면 `SELECT FLAVOR, TOTAL_ORDER`처럼 쉼표로 나열합니다. 다만 이 문제 제출 답에는 FLAVOR만 필요합니다.
- SELECT 뒤에는 컬럼뿐 아니라 `AVG(DAILY_FEE)`, `2 * 3` 같은 **계산식·함수 결과**도 올 수 있습니다.
- `SELECT *`: 모든 열을 출력합니다. 요구한 열만 출력해야 하는 이 문제에서는 쓰지 않습니다.
- `FROM FIRST_HALF`: **어느 테이블에서 조회할지** 지정합니다. FLAVOR는 열 이름, FIRST_HALF는 테이블 이름입니다.
- 한 행은 예시에서 아이스크림 맛 하나의 정보이고, 열은 출하 번호·맛·주문량 같은 항목입니다.

### ORDER BY, DESC, ASC

- `ORDER BY`: 조회 결과의 행 순서를 정합니다. 원본 테이블의 데이터를 수정하는 명령이 아닙니다.
- `DESC`: 내림차순입니다. 숫자는 큰 값부터 작은 값으로, 예를 들면 3200 → 3150 → 3100입니다.
- `ASC`: 오름차순입니다. 숫자는 작은 값부터 큰 값으로, 예를 들면 105 → 109입니다. 생략 시 기본값입니다.
- 방향은 **바로 앞 정렬 기준에 각각 적용**합니다. `TOTAL_ORDER DESC, SHIPMENT_ID ASC`는 주문량만 내림차순, 출하 번호는 오름차순입니다.
- 정렬 기준을 여러 개 쓰면 **왼쪽 기준이 우선**입니다. 첫 기준이 같은 행들끼리만 다음 기준으로 비교합니다.
- 이 문제에서는 SELECT에 없는 TOTAL_ORDER와 SHIPMENT_ID로도 정렬할 수 있습니다. **정렬에 쓰는 열과 결과로 보여 줄 열은 다를 수 있습니다.**
- ORDER BY를 생략하면 원하는 순서가 보장되지 않습니다. 출하 번호가 작아도 주문량이 적으면 뒤로 갑니다.

### 왜 AND가 아니라 쉼표야?

- **쉼표는 목록을 나열**합니다. 여기서는 ‘첫 정렬 기준, 두 번째 정렬 기준’입니다.
- **AND는 조건을 연결하는 논리 연산자**입니다. 두 조건이 모두 참인지 판단할 때 씁니다. WHERE나 ON에서 자주 사용합니다.

```sql
-- 정렬 기준 두 개를 나열
ORDER BY TOTAL_ORDER DESC, SHIPMENT_ID ASC

-- 두 조건을 모두 만족하는 행만 선택하는 예시
WHERE TOTAL_ORDER >= 3000 AND SHIPMENT_ID < 110
```

- `ORDER BY TOTAL_ORDER DESC AND SHIPMENT_ID ASC`는 정렬 목록 문법이 아니어서 오류입니다.
- AND가 ORDER BY 안에서 절대 금지된다는 뜻은 아닙니다. `ORDER BY (TOTAL_ORDER >= 3000 AND SHIPMENT_ID < 110)`처럼 **논리식 하나의 결과**로 정렬할 수는 있지만, 두 열을 우선순위대로 정렬하는 것과는 다른 작업입니다.
- 기억하기: **나열은 쉼표, 조건의 ‘그리고’는 AND**입니다. JavaScript의 `&&`가 하던 역할을 SQL에서는 보통 AND로 적습니다.

### WHERE와 ORDER BY 구분

- WHERE는 **어떤 행을 남길지**, ORDER BY는 **남은 행을 어떤 순서로 보여 줄지** 정합니다.
- 이 문제는 모든 맛을 조회하므로 WHERE가 필요 없습니다. 총주문량을 새로 더하라는 요구도 없어서 SUM이나 GROUP BY도 필요 없습니다.
- SELECT, FROM, ORDER BY, ASC, DESC는 SQL 키워드입니다. AND는 논리 연산자이며, 어느 것도 `AVG()` 같은 함수 호출이 아닙니다.

## 시간·공간 복잡도 쉽게 보기

- 행이 N개라면 DB가 각 행의 주문량과 출하 번호를 보고 순서를 정해야 합니다.
- 별도로 비교 정렬을 하는 실행 계획이면 보통 시간 O(N log N)으로 설명합니다. 단순히 한 번 읽는 것보다 비교·순서 맞추기 작업이 더 필요합니다.
- 두 정렬 기준을 적었다고 정렬을 N번 더 하는 것은 아닙니다. 두 행을 비교할 때 ‘주문량 우선, 같으면 출하 번호’라는 규칙을 쓰는 것입니다.
- 정렬용 메모리나 임시 디스크 공간이 필요할 수 있습니다. 적합한 인덱스로 정렬을 피하는 경우도 있어 SQL 전체 공간·시간은 실행 계획 없이 확정하지 않습니다.
- 실제 처리 방식은 EXPLAIN으로 확인합니다. 여기서는 **요구한 우선순위와 방향을 정확히 쓰는 것**이 먼저입니다.
