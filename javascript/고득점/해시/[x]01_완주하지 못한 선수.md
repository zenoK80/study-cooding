# 01. 완주하지 못한 선수

[프로그래머스 원문](https://school.programmers.co.kr/learn/courses/30/lessons/42576?language=javascript)

- 분류: 해시
- 문제 번호: 42576

## 문제 설명

수많은 마라톤 선수들이 마라톤에 참여하였습니다. 단 한 명의 선수를 제외하고는 모든 선수가 마라톤을 완주하였습니다.

마라톤에 참여한 선수들의 이름이 담긴 배열 `participant`와 완주한 선수들의 이름이 담긴 배열 `completion`이 주어질 때, 완주하지 못한 선수의 이름을 return 하도록 `solution` 함수를 작성해주세요.

## 제한사항

- 마라톤 경기에 참여한 선수의 수는 1명 이상 100,000명 이하입니다.
- `completion`의 길이는 `participant`의 길이보다 1 작습니다.
- 참가자의 이름은 1개 이상 20개 이하의 알파벳 소문자로 이루어져 있습니다.
- 참가자 중에는 동명이인이 있을 수 있습니다.

## 입출력 예

| participant | completion | return |
| --- | --- | --- |
| ["leo", "kiki", "eden"] | ["eden", "kiki"] | "leo" |
| ["marina", "josipa", "nikola", "vinko", "filipa"] | ["josipa", "filipa", "marina", "nikola"] | "vinko" |
| ["mislav", "stanko", "mislav", "ana"] | ["stanko", "ana", "mislav"] | "mislav" |

## 입출력 예 설명

- 예제 #1: `"leo"`는 참여자 명단에는 있지만, 완주자 명단에는 없기 때문에 완주하지 못했습니다.
- 예제 #2: `"vinko"`는 참여자 명단에는 있지만, 완주자 명단에는 없기 때문에 완주하지 못했습니다.
- 예제 #3: `"mislav"`는 참여자 명단에는 두 명이 있지만, 완주자 명단에는 한 명밖에 없기 때문에 한 명은 완주하지 못했습니다.

## 문제 코드

```javascript
function solution(participant, completion) {
    var answer = '';
    return answer;
}
```

## 내가 푼 답

현재 코드는 참가자 수 계산 결과를 객체에 저장하도록 수정된 상태입니다.

```javascript
function solution(participant, completion) {
    var answer = '';
    if( participant.length > 100000 || participant.length < 1 ) return;
    if( (participant.length - completion.length) !== 1) return;
    let object = Object.create(null);
    participant.map(a =>  object[a] = (object[a] ?? 0) + 1);
    completion.map(b => object[b] -= 1 );
    answer =  Object.keys(object).find(name => object[name] === 1);
    return answer;
}
```

### 이전 실수 — 계산 후 저장하기

```javascript
participant.map(a => object[a] = (object[a] ?? 0) + 1);
```

- 이전에는 `object[a] =`와 닫는 괄호가 빠졌습니다. 현재 코드처럼 계산 결과를 저장해야 합니다. 계산만 하면 객체에 값이 남지 않습니다.
- map으로도 동작하지만, 반환 배열을 사용하지 않으므로 forEach가 더 적합합니다. 여기서는 작성한 map을 유지했습니다.

### Object.keys()와 find()

- `Object.keys(객체)` : 객체 자신의 열거 가능한 문자열 키를 새 배열로 반환합니다. 이 문제에서는 저장한 선수 이름들입니다. 인원수 값은 포함하지 않습니다.
- `배열.find(조건함수)` : 조건이 참인 첫 원소를 반환합니다. 여기서는 이름 문자열이며, 없으면 `undefined`입니다.
- `name => object[name] === 1` : 이름을 하나씩 받아 그 이름에 저장된 인원수가 1인지 확인합니다. 조건은 참·거짓을 만들지만 find가 반환하는 것은 해당 이름입니다.

```javascript
// 집계와 차감을 마친 객체가 아래와 같다고 가정
const object = Object.create(null);
object['kim'] = 1;
object['lee'] = 0;

let answer = Object.keys(object);
console.log(answer); // ['kim', 'lee']: 키만 담은 배열

answer = Object.keys(object).find(name => object[name] === 1);
console.log(answer); // kim: 인원수가 1인 이름 문자열
```

- `answer = Object.keys(object)`까지만 하면 모든 이름의 배열이 들어갑니다. 값이 0인 lee도 키가 삭제된 것은 아니라서 포함됩니다.
- 배열을 그대로 return하면 문제에서 요구한 이름 문자열이 아니므로 오답입니다. 콘솔의 따옴표·배열 표시 모양은 실행 환경에 따라 조금 다를 수 있습니다.

## 다른 방법

### 복잡도 읽는 기준

- `n` = 참가자 수, `n - 1` = 완주자 수, `u` = 서로 다른 이름 수입니다. `u`는 최대 n입니다.
- **시간 복잡도**는 작업량, **공간 복잡도**는 메모리 사용량의 증가 정도입니다. 여기서는 입력 배열을 제외한 **추가 공간**을 계산합니다.
- **평균 시간**은 가정한 동작에서의 평균 비용, **최악 시간**은 가장 불리한 경우의 비용입니다. 실제 실행 시간(초)을 계산하는 것은 아닙니다.
- 아래 집계 풀이는 객체·Map의 조회·저장을 평균 `O(1)`로 보는 일반적인 해시 구현 기준입니다. JavaScript가 모든 엔진의 최악 비용을 보장하는 것은 아닙니다.
- 이름 길이는 최대 20글자로 제한돼 있으므로 이름 처리 비용은 고정 크기로 봅니다. 여러 단계를 순서대로 실행하면 비용을 더하고, 고정 배수와 작은 항은 생략합니다.

### (1) Map과 for...of — 이름별 인원수 저장

```javascript
function solution(participant, completion) {
  const counts = new Map();
  // 참가자: 같은 이름이 나올 때마다 1명 추가
  for (const name of participant) {
    const count = counts.get(name) ?? 0;
    counts.set(name, count + 1);
  }
  // 완주자: 해당 이름의 인원수에서 1명 차감
  for (const name of completion) {counts.set(name, counts.get(name) - 1);}
  // 1명이 남아 있는 이름 반환
  for (const [name, count] of counts) {if (count === 1) return name;}
}
```

- **시간 계산**: 참가자 n명 집계 + 완주자 n−1명 차감 + 이름 최대 u개 확인 → `O(n + (n - 1) + u)` → 평균 `O(n)`.
- **왜 곱하지 않나?** 세 반복문이 안에 겹쳐 있지 않고 차례로 실행되므로 횟수를 더합니다. get/set도 위 가정에서는 평균 일정한 비용입니다.
- **추가 공간 계산**: Map에 이름·인원수 쌍 u개 저장 → `O(u)`, 이름이 모두 다르면 `O(n)`. name과 count는 매번 생겨도 전부 모아 저장하지 않습니다.
- **최악 주의**: 마지막 탐색은 최대 u개입니다. 해시 충돌로 조회·저장이 느려지는 단순 해시 구현은 전체가 최악 `O(n²)`까지 갈 수 있지만, 실제 엔진의 최악 비용은 구현에 따라 다릅니다.

### (2) 객체와 forEach — 인덱스 없이 집계

```javascript
function solution(participant, completion) {
  const counts = Object.create(null);
  participant.forEach(name => {counts[name] = (counts[name] ?? 0) + 1;});
  completion.forEach(name => {counts[name] -= 1;});
  for (const name in counts) {if (counts[name] === 1) return name;}
}
```

- **시간 계산**: 첫 forEach n번 + 둘째 forEach n−1번 + 객체 키 최대 u개 순회 → `O(n + (n - 1) + u)` → 평균 `O(n)`.
- **추가 공간 계산**: 객체에 이름별 인원수 u개 저장 → `O(u)`, 최악 `O(n)`. forEach는 map처럼 반환용 배열을 만들지 않습니다.
- **최악 주의**: 객체 조회·저장도 엔진 구현에 영향을 받습니다. 위 `O(n)`은 해시 조회·저장 평균 비용을 가정한 분석이며, 모든 상황의 최악 시간 보장은 아닙니다.
- **(5) 기본 for 풀이도 같은 계산**: 기본 for를 forEach로 바꿨을 뿐, 처리하는 원소 수와 저장하는 데이터는 같습니다.

### (3) 정렬과 for — 나란히 놓고 비교

```javascript
function solution(participant, completion) {
  const participants = [...participant].sort();
  const finishers = [...completion].sort();
  for (let i = 0; i < participants.length; i++) {
    if (participants[i] !== finishers[i]) return participants[i];
  }
}
```

- 이름을 같은 기준으로 정렬하면, 처음 어긋나는 위치의 참가자가 정답입니다. 동명이인도 각각 남아 있어 비교할 수 있습니다.
- 마지막 참가자가 정답이면 같은 위치의 완주자는 `undefined`이므로 역시 다르다고 판단합니다. 복사 후 정렬하므로 원본 배열은 바꾸지 않습니다.

- **시간 계산**: 배열 두 개 복사 `O(n)` + 정렬 두 번 `O(n log n)` + 위치 비교 최대 `O(n)` → 전체 `O(n log n)`.
- **왜 정렬 두 번도 같은 표기인가?** 두 배열 크기가 거의 같으므로 대략 `2 × n log n`이며, 고정 배수 2를 생략합니다. 비교보다 정렬 비용이 더 크게 증가합니다.
- **추가 공간 계산**: 복사본에 n개와 n−1개 저장 → `2n - 1`개 → 복사 공간 `O(n)`. 여기에 sort가 내부적으로 쓰는 작업 공간도 더해야 합니다.
- **평균·최악 주의**: 위 시간은 `O(n log n)` 정렬을 가정한 일반적 분석입니다. sort의 평균·최악 시간과 내부 메모리는 엔진에 따라 다르며, 내부 공간이 `O(n)` 이하라면 전체 추가 공간도 `O(n)`입니다.

### (4) reduce와 find — 배열 메서드 연습용

```javascript
function solution(participant, completion) {
  const counts = participant.reduce((acc, name) => {
    acc[name] = (acc[name] ?? 0) + 1;
    return acc;
  }, Object.create(null));
  completion.forEach(name => {counts[name] -= 1;});
  return Object.keys(counts).find(name => counts[name] === 1);
}
```

- `acc`는 누적해서 사용하는 객체입니다. 매번 같은 객체에 개수를 기록하고 `return acc`로 다음 반복에 넘깁니다.
- `Object.keys(counts)`로 이름 배열을 만든 뒤, `find()`로 인원수가 1인 이름을 찾습니다.
- `배열.reduce((누적값, 현재원소) => {return 다음누적값;}, 시작값)`.
- **시간 계산**: reduce n번 + forEach n−1번 + Object.keys로 키 u개 수집 + find로 최대 u개 확인 → `O(n + (n - 1) + u + u)` → 평균 `O(n)`.
- **추가 공간 계산**: counts 객체 u개 항목 + Object.keys가 만든 이름 배열 u개 → `O(u + u)` → `O(u)`, 최악 `O(n)`.
- **return acc는 복사가 아님**: 매번 같은 객체를 다음 반복에 전달합니다. 객체 n개를 따로 만들어 저장하는 코드가 아닙니다.
- **최악 주의**: find가 마지막 이름까지 확인해도 탐색 자체는 `O(u)`입니다. 전체 평균 `O(n)`은 객체 조회·저장 비용에 대한 위 가정을 따르며, 엔진별 최악 시간 보장은 아닙니다.

### (5) 객체와 기본 for — 이전에 작성한 풀이

```javascript
function solution(participant, completion) {
  const counts = Object.create(null);

  for (let i = 0; i < participant.length; i++) {
    const name = participant[i];
    counts[name] = (counts[name] ?? 0) + 1;
  }
  for (let i = 0; i < completion.length; i++) {
    const name = completion[i];
    counts[name] -= 1;
  }
  for (const name in counts) {if (counts[name] === 1) return name;}
}
```

- **시간 계산**: 참가자 n명 + 완주자 n−1명 + 이름 최대 u개 → 평균 `O(n)`입니다. 객체 조회·저장 평균 `O(1)` 가정입니다.
- **추가 공간 계산**: 이름별 인원수 u개 → `O(u)`, 이름이 모두 다르면 `O(n)`입니다.

### (6) 완주자 집계와 find — 반대 방향으로 찾기

```javascript
function solution(participant, completion) {
  const counts = completion.reduce((acc, name) => {
    acc[name] = (acc[name] ?? 0) + 1;
    return acc;
  }, Object.create(null));
  return participant.find(name => {
    if ((counts[name] ?? 0) === 0) return true;
    counts[name] -= 1;
    return false;
  });
}
```

- **배울 점**: 이번에는 완주자를 먼저 셉니다. 참가자 이름에 해당하는 완주 인원이 없으면 그 참가자가 정답이고, 있으면 1명을 사용한 것으로 차감합니다.
- 예시: 완주자 `['kim', 'lee']` → `{kim: 1, lee: 1}`. 참가자 `['kim', 'kim', 'lee']`에서 첫 kim은 1을 차감하고, 두 번째 kim은 남은 인원이 0이므로 반환합니다.
- 콜백의 `return true`는 find에게 ‘이 이름을 선택하라’는 뜻입니다. 바깥 `return participant.find(...)`가 그 이름을 solution의 결과로 반환합니다.
- **시간 계산**: 완주자 n−1명 집계 + 참가자 최대 n명 확인 → 평균 `O(n)`. **추가 공간**: 완주자의 서로 다른 이름 수만큼 저장 → 최악 `O(n)`. 해시 조회·저장 평균 `O(1)` 가정입니다.

### (7) Map.has와 if — 기본값 연산자 없이 명시적으로 분기

```javascript
function solution(participant, completion) {
  const counts = new Map();
  for (const name of completion) {
    if (counts.has(name)) {counts.set(name, counts.get(name) + 1);}
    else {counts.set(name, 1);}
  }
  for (const name of participant) {
    if (!counts.has(name) || counts.get(name) === 0) return name;
    counts.set(name, counts.get(name) - 1);
  }
}
```

- **배울 점**: `??`로 압축하지 않고 ‘처음 나온 이름인가?’를 if로 직접 확인합니다. 개수 계산이 헷갈리면 이 방식부터 읽어도 됩니다.
- `counts.has(name)` : 해당 키가 있는지 확인합니다. 키가 있어도 저장된 값이 0일 수 있으므로, 반환 조건에서 0인지도 별도로 검사합니다.
- **시간 계산**: 완주자 n−1명 + 참가자 최대 n명 → 평균 `O(n)`. **추가 공간**: 완주자 이름별 Map → 최악 `O(n)`. 해시 조회·저장 평균 `O(1)` 가정입니다.

### (8) 정렬과 pop — 뒤에서 하나씩 비교

```javascript
function solution(participant, completion) {
  const participants = [...participant].sort();
  const finishers = [...completion].sort();
  while (participants.length > 0) {
    const name = participants.pop();
    if (name !== finishers.pop()) return name;
  }
}
```

- **배울 점**: 정렬 후 앞에서 비교하는 대신, 맨 뒤의 이름을 하나씩 꺼내 비교합니다. 동명이인도 한 명씩 꺼냅니다.
- 예시: 정렬된 참가자 `['kim', 'kim', 'lee']`, 완주자 `['kim', 'lee']` → lee끼리 일치 → kim끼리 일치 → 남은 kim과 undefined가 다르므로 kim 반환.
- **시간 계산**: 복사 `O(n)` + 일반적인 정렬 `O(n log n)` + 최대 n번 꺼내기 `O(n)` → `O(n log n)`. **추가 공간**: 복사 배열 `O(n)` + 정렬 내부 공간. sort의 세부 비용은 엔진 구현에 따라 다릅니다.
- 올려준 원문은 원본 배열을 정렬·삭제합니다. 여기서는 복사본만 바꿔 입력을 보존했습니다.

### (9) 한 줄 압축 풀이 — 해석 연습용

```javascript
var solution=(_,$)=>_.find(_=>!$[_]--,$.map(_=>$[_]=($[_]|0)+1))
```

- **전체 의도**: 완주자 이름별 개수를 먼저 저장하고, 참가자를 보며 하나씩 차감합니다. 남은 완주 인원이 없는 첫 참가자를 반환합니다.
- 원문 그대로입니다. 입력 배열에 이름별 속성을 추가하므로 원본을 변경하고, `length` 같은 이름에서 오답이 날 수 있습니다. 안전한 정답 풀이가 아니라 문법 해석용입니다.

#### 변수명부터 풀기

```javascript
var solution = (participant, completion) => participant.find(
  name => !(completion[name]--),
  completion.map(name => completion[name] = (completion[name] | 0) + 1)
);
```

- 바깥 `_`는 participant, `$`는 completion입니다. 둘 다 사용할 수 있는 변수명이지만 역할을 알아보기 어렵습니다.
- 두 콜백의 `_`는 각각 현재 이름입니다. 바깥 `_`와 이름만 같고 다른 범위의 변수라서, 위에서는 모두 name으로 바꿨습니다.
- `$`는 특별한 JavaScript 기능이 아니라 그냥 변수명입니다.

#### 1. 뒤에 있는 map이 왜 먼저 동작하나?

- `find(조건함수, thisArg)`에서 두 번째 인자는 원래 콜백의 this로 사용할 값입니다. 두 번째 조건함수가 아닙니다.
- JavaScript는 find에 전달할 인자들을 먼저 계산하고, 그다음 find를 실행합니다. 첫 인자의 화살표 함수는 만들어질 뿐 아직 실행되지 않습니다.
- 따라서 두 번째 인자의 `completion.map(...)`이 먼저 끝납니다. 이 과정에서 완주자 개수를 저장합니다.
- map이 반환한 배열은 thisArg로 전달되지만, 첫 콜백은 자신만의 this가 없는 화살표 함수이고 this를 쓰지도 않아서 여기서는 쓸모가 없습니다. map의 저장 작업만 이용한 압축입니다.

#### 2. ($[_] | 0) + 1

- `completion[name]` : 배열에서 이름을 검색하는 것이 아니라, 배열 객체에 붙인 이름 속성을 조회합니다.
- `|` 하나는 **비트 OR 연산자**입니다. 기본값을 고르는 `||`와 다릅니다.
- 이 코드처럼 Number 값에 `값 | 0`을 사용하면 32비트 정수로 변환됩니다. `undefined | 0` → 0, `2 | 0` → 2입니다.
- 그 결과에 1을 더해 `completion[name]`에 저장합니다. 일반적인 이름은 처음이면 1, 다시 나오면 2가 됩니다.
- `| 0`은 `?? 0`과 같은 기능이 아닙니다. 소수 부분도 버리고 큰 숫자도 32비트 범위로 변환하므로 일반적인 기본값 처리용으로 따라 쓰지 않습니다.

```javascript
// completion = ['kim', 'lee']라고 가정
// 배열 원소는 그대로 둔 채, 별도 속성을 붙이는 방식
completion['kim'] = 1;
completion['lee'] = 1;
// completion[0]은 여전히 'kim', completion['kim']은 숫자 1
```

#### 3. !$[_]--

- 괄호로 풀면 `!(completion[name]--)`입니다. `--`가 먼저 현재 값을 숫자로 바꾸고, 감소 전 숫자를 표현식 결과로 내놓으면서 저장값을 1 줄입니다.
- 그 감소 전 숫자에 `!`를 적용합니다. 남은 인원이 1 이상이면 false, 0이면 true입니다.
- 저장된 속성이 없으면 undefined가 숫자 변환 과정에서 NaN이 됩니다. `!NaN`도 true라서 그 이름을 선택합니다. 해당 속성에는 NaN이 저장됩니다.
- find는 조건 결과가 true인 첫 **이름**을 반환합니다. 화살표 함수 바깥의 중괄호를 생략했으므로 solution도 그 이름을 자동 반환합니다.

```javascript
// 참가자 ['kim', 'kim', 'lee'], 완주자 ['kim', 'lee']
// map 집계 후 kim: 1, lee: 1
// 첫 kim: 감소 전 1 → !1은 false, 저장값은 0
// 다음 kim: 감소 전 0 → !0은 true, 저장값은 -1
// find가 두 번째 kim에서 멈추고 'kim' 반환
```

#### 실행 순서 그대로 펼친 코드

아래도 원문의 위험한 배열 속성 저장을 그대로 유지한 해설입니다. 더 안전한 풀이로 바꾼 것이 아닙니다.

```javascript
function solution(participant, completion) {
  completion.map(name => {
    completion[name] = (completion[name] | 0) + 1;
    return completion[name];
  });
  return participant.find(name => {
    const before = completion[name]--;
    return !before;
  });
}
```

- **반례**: 참가자 `['length', 'kim']`, 완주자 `['kim']`이면 정답은 `'length'`인데 원문은 undefined를 반환합니다. `completion['length']`가 개수가 아니라 배열 길이 1로 시작하고, 감소시키면 배열까지 잘리기 때문입니다.
- **복잡도**: 속성 충돌 없이 동작하고 평균 속성 접근이 `O(1)`이라는 가정에서 map n−1번 + find 최대 n번 → 평균 `O(n)`. 이름 속성 외에 사용하지 않는 map 결과 배열도 만들어 추가 공간은 `O(n)`입니다.
- 한 줄이라고 더 빠르거나 더 정확한 것은 아닙니다. 배울 부분은 **인자 평가 순서·후위 감소·비트 연산**이며, 제출용은 (6)이나 (7)처럼 이름 저장소를 분리한 풀이가 적합합니다.

## 정리

### 이번에 추가한 문법

- `Map.has(키)` : 실제 사용은 `counts.has(name)`처럼 만든 Map에서 호출합니다. 키가 있으면 true, 없으면 false입니다. `get()`은 그 키에 저장된 값을 가져옵니다.
  - 예시: `counts.set('kim', 0)` 후 `counts.has('kim')` → true, `counts.get('kim')` → 0.
- `pop()` : 배열의 마지막 원소를 제거하고 그 원소를 반환합니다. 빈 배열에서는 undefined를 반환합니다.
  - 예시: `const arr = ['kim', 'lee']; const name = arr.pop();` → name은 `'lee'`, arr는 `['kim']`.
- `while (조건)` : 조건이 참인 동안 반복합니다. (8)은 pop으로 배열 길이가 줄어들므로 결국 반복이 끝납니다.
- `find()`의 콜백에서 true 반환 : 현재 원소를 선택하고 탐색을 끝냅니다. false 반환 : 다음 원소를 확인합니다. find 자체의 결과는 true가 아니라 선택한 원소입니다.
- `++`·`--` : 저장된 숫자를 1 증가·감소시킵니다. 값이 undefined라면 NaN이 되므로 먼저 초기화해야 합니다.
- `obj[name]--`는 감소 전 값을 표현식의 결과로 사용한 뒤 저장된 값을 줄입니다. `!obj[name]--`처럼 겹쳐 쓰면 해석하기 어려우므로 조건 검사와 차감을 나누는 편이 좋습니다.

### 올려준 코드 중 주의할 것

- **`_`, `$`로 압축한 한 줄 풀이**: 변수명 자체는 가능하지만, 배열을 이름별 저장소로 겸용하고 후위 감소·부정·비트 연산까지 섞어 읽기 어렵습니다. `length`, `map` 같은 이름이 배열 속성과 충돌할 수도 있어 그대로 추천하지 않습니다.
- **참가자·완주자를 한 반복문에서 처리하는 Map 풀이**: 길이가 1 차이라 마지막 `completion[i]`는 undefined입니다. 원문은 Map에 `undefined → -1`도 저장합니다. 정답 탐색에는 보통 영향이 없지만, 완주자를 처리할 때 `i < completion.length`로 제한하는 편이 명확합니다.
- **`{}`로 이름 집계**: 상속된 속성 이름과 충돌할 수 있어 추가 풀이에서는 `Object.create(null)`로 바꿨습니다.
- **`let hashed = []`로 이름 집계**: 배열도 속성을 저장할 수 있지만, 선수 이름이 `length` 등과 겹치면 문제가 됩니다. 배열 대신 객체·Map을 사용합니다.
- **`for (i = 0; ...)`**: i 선언이 빠져 있습니다. `let i = 0`으로 선언해야 하며, 엄격 모드에서는 미선언 변수 대입이 오류입니다.
- **`for...in`으로 배열 순회**: 배열 값이 아니라 문자열 키를 꺼내고 추가 속성도 포함할 수 있습니다. 정렬 비교에는 기본 for문이 더 명확합니다.
- **includes + indexOf + splice**: 한 명씩 삭제하면 논리는 맞지만 반복 검색·이동 때문에 최악 `O(n²)`입니다.
- **쉼표 연산자로 압축한 reduce**: `(대입식, obj)`는 대입 후 마지막 obj를 반환합니다. (6)에서는 같은 뜻을 대입문과 `return acc`로 풀어 썼습니다.
- 지금은 모든 풀이를 외우기보다 **(7)의 키 존재 확인 → 처음이면 1 저장 → 다시 나오면 1 증가**를 먼저 이해하면 됩니다.

### 풀이 흐름

- 참가자는 이름별로 1씩 더하고, 완주자는 1씩 뺍니다. 마지막에 1이 남은 이름이 정답입니다.
- 예시: 참가자 `['kim', 'kim', 'lee']` → 집계 `{kim: 2, lee: 1}` → 완주자 `['kim', 'lee']` 차감 → `{kim: 1, lee: 0}` → `'kim'` 반환.
- `return name` : 문제에서 요구하는 답이 개수가 아니라 이름이므로 이름만 반환합니다. `return`은 solution 함수를 즉시 종료합니다.
- 입력 조건은 문제에서 보장하므로 범위 검사는 없어도 됩니다.

### 객체·키·값

- 자료구조 : 데이터를 담고 정리하는 방식입니다. 배열, 객체, Map 등으로 데이터를 정리할 수 있습니다.
- `{kim: 2}` : `kim`이 키(이름표), `2`가 값(저장한 내용)입니다. 값이 원래 개수를 뜻하는 것은 아니고, 이 문제에서 개수를 저장한 것입니다.
- `counts`는 저장소 변수명, `name`은 선수 이름을 담는 변수명, `count`는 인원수를 담는 변수명입니다. 직접 붙인 이름입니다.
- 이 풀이의 저장 형태는 `{kim: 2, lee: 1}`입니다. `[{name: 'kim', count: 2}, ...]`처럼 객체들을 담은 배열을 만드는 것이 아닙니다.

### 대괄호 []와 점 .

- `counts.kim`과 `counts['kim']` : 둘 다 글자 그대로 `kim`이라는 키의 값을 조회합니다.
- `counts[name]` : 변수 `name`에 들어 있는 값을 키로 사용합니다. `name`이 `'kim'`이면 `counts['kim']`과 같습니다.
- `counts.name` : 변수 name을 읽지 않고, 글자 그대로 `name`이라는 키를 찾습니다.
- `counts[name]`만 쓰면 조회만 합니다. `counts[name] = 1`로 대입하면 키가 없을 때 새로 생기고, 있으면 값이 바뀝니다.

```javascript
const counts = Object.create(null);
const name = 'kim';
counts[name];     // undefined: 조회만 했으므로 아직 키 없음
counts[name] = 1; // kim이라는 키에 1 저장
counts.kim;      // 1
counts['kim'];   // 1
counts[name];    // 1: name 변수의 값이 'kim'이므로
counts.name;     // undefined: 'name'이라는 키는 저장하지 않았음
```

### Object.create(null)과 {}

- `{}` : 기본 기능을 물려받는 객체입니다. 직접 저장하지 않은 이름도 물려받은 속성에서 조회될 수 있습니다.
- `Object.create(null)` : 물려받는 속성이 없는 빈 객체입니다. 내가 저장한 이름별 인원수만 조회하려고 사용합니다.
- `Object.create(대상)` : 대상을 물려받는 새 객체를 만듭니다. `null`은 아무것도 물려받지 않겠다는 뜻이고, `Object.create()`처럼 생략하면 오류입니다.
- 예시: `{}`에서 `'constructor'`를 조회하면 기본으로 물려받은 함수가 나옵니다. 같은 이름의 선수를 셀 때 방해되므로 물려받지 않는 객체를 썼습니다.
- 일반 객체에는 Map의 `.get()`·`.set()`이 기본 제공되지 않습니다. `counts[name]`으로 조회하고 `counts[name] = 값`으로 저장합니다.

### ??와 인원수 계산

- `값 ?? 기본값` : 값이 `null` 또는 `undefined`일 때만 기본값을 사용합니다. `0`, `false`, `''`은 그대로 사용합니다.
- `counts[name] = (counts[name] ?? 0) + 1` : 오른쪽에서 기존 인원수를 읽어 1을 더한 뒤 왼쪽에 저장합니다. 처음 나온 이름이면 0에서 시작합니다.
- 첫 `kim` : 기존 값 `undefined` → `0 + 1` → `{kim: 1}`.
- 다음 `kim` : 기존 값 `1` → `1 + 1` → `{kim: 2}`. 매번 0으로 초기화하는 것이 아닙니다.
- 첫 `lee` : 기존 값 `undefined` → `0 + 1` → `{kim: 2, lee: 1}`. kim의 값은 그대로 남습니다.
- `counts[name] -= 1` : `counts[name] = counts[name] - 1`의 축약형입니다. 키를 삭제하는 것이 아니라 저장된 숫자를 줄입니다.

### Map·new Map()·배열.map()

- `Map` : JavaScript에 기본 제공되는 내장 생성자입니다. 여기서 생성자는 저장소를 만드는 기능이라고 이해하면 됩니다.
- `new Map()` : 키와 값을 짝지어 저장하는 빈 Map을 실제로 만듭니다. Map도 객체의 한 종류지만 일반 객체 `{}`와 사용 방법이 다릅니다.
- 일반 객체의 키는 문자열·심벌이고, Map은 숫자·객체 등도 키로 사용할 수 있습니다. 둘 다 값으로 개수뿐 아니라 다른 데이터도 저장할 수 있습니다.
- `counts.set(키, 값)` : Map의 내장 메서드. 해당 키에 값을 저장합니다. 같은 키면 덮어쓰며 자동으로 더하지는 않습니다.
  - 예시: `counts.set('kim', 1); counts.set('kim', 2);` → kim에 2 저장.
- `counts.get(키)` : Map의 내장 메서드. 키 자체가 아니라 그 키에 저장된 값을 반환합니다. 없으면 `undefined`입니다.
  - 예시: 위 저장 후 `counts.get('kim')` → `2`, `counts.get('lee')` → `undefined`.
- `const count = counts.get(name) ?? 0` : 현재 인원수를 읽습니다. 아직 저장하지 않은 이름이면 0을 사용하며, 이 줄은 저장하지 않습니다.
- `counts.set(name, count + 1)` : 해당 이름의 인원수를 1 늘려 저장합니다. name이 `'kim'`, count가 2이면 `counts.set('kim', 3)`입니다.
- `counts.set(count, count + 1)`은 다른 뜻입니다. count가 2이면 숫자 2라는 키에 3을 저장하므로 kim의 인원수는 바뀌지 않습니다.
- 배열의 `.map()` : 원소마다 변환한 새 배열을 만드는 메서드로, 위 Map과 별개입니다. 이름별 개수를 자동으로 합쳐 주지 않습니다.

### for·for...of·for...in과 const

- `for (let i = 0; i < participant.length; i++)` : 인덱스 i를 증가시키며 반복합니다. `participant[i]`로 이름을 꺼냅니다.
- `for (const name of participant)` : 배열의 값인 이름을 하나씩 꺼냅니다. 문자열, Map 등 반복 가능한 값에도 사용할 수 있습니다.
- `for (const name in counts)` : 객체의 키인 이름을 하나씩 꺼냅니다. 일반적으로 물려받은 열거 가능한 문자열 키도 포함하지만, 이 풀이의 객체는 상속 속성이 없습니다.
- `const` : 같은 변수에 다른 값을 재대입할 수 없다는 뜻입니다. 프로그램 전체에서 같은 변수명을 한 번만 써야 한다는 뜻이 아닙니다.
- 스코프 : 변수를 사용할 수 있는 범위입니다. 각각의 for문에 선언한 name은 서로 다른 범위의 변수입니다.
- `for...of`의 const 변수는 매 반복마다 새로 생깁니다. 반복문 본문 안의 `const count`도 실행할 때마다 새로 만들어집니다.
- `const counts`로 선언해도 객체 내부 값은 변경할 수 있습니다. `counts[name] = 2`는 가능하지만 `counts = 다른객체`는 불가능합니다.

### [name, count] 구조 분해 할당

- 구조 분해 할당 : 배열이나 객체에서 값을 꺼내 여러 변수로 나눠 담는 문법입니다.
- `const [name, count] = ['kim', 2]` : name에는 `'kim'`, count에는 `2`가 들어갑니다.
- Map을 for...of로 순회하면 각 항목이 `[키, 값]` 배열로 나옵니다. 그래서 `for (const [name, count] of counts)`로 받습니다.
- Map 자체가 배열이라는 뜻은 아닙니다. 순회할 때 나오는 항목이 배열이라 `{}`가 아닌 `[]`로 받는 것입니다.

### 다른 풀이에 나온 문법

- `[...배열]` : 원소를 펼쳐 새 배열로 복사합니다. 이 문제에서는 복사본만 정렬하려고 사용합니다.
- `.sort()` : 배열을 정렬하며 그 배열 자체를 바꿉니다. 이 문제는 소문자 이름이므로 기본 문자열 정렬로 비교할 수 있습니다.
- `!==` : 두 값이 엄격히 다른지 비교합니다. 정렬 후 같은 위치의 이름이 다르면 그 참가자가 정답입니다.
- `Object.keys(counts)` : 객체 자신의 키들을 배열로 반환합니다. `{kim: 1, lee: 0}` → `['kim', 'lee']`.
- 콜백 : forEach, map, find 등에 전달해서 메서드가 실행하도록 하는 함수입니다. `name => counts[name] === 1`도 콜백입니다.
- `forEach()`의 콜백에서 return해도 solution은 종료되지 않습니다. 그래서 반환할 이름을 찾을 때는 for문이나 find를 사용했습니다.
- `.map()`도 집계 작업을 실행할 수는 있지만 불필요한 결과 배열을 만듭니다. 새 배열이 필요 없을 때는 forEach나 for문이 더 알맞습니다.

### 어떤 풀이부터 볼까?

- 내가 푼 답의 map 방식과 (5)의 객체 + 기본 for문은 이름별 인원수를 세는 원리가 같습니다. 먼저 익숙한 반복 방식으로 이해하면 됩니다.
- 정렬 풀이는 개수 저장 없이 두 명단을 비교하는 다른 접근입니다. reduce 풀이는 익숙해진 뒤 봐도 됩니다.
- `filter()`·`includes()`로 이름이 있는지만 확인하면 동명이인을 구분하지 못합니다. 같은 이름을 매번 전부 검색해 세면 최대 10만 명에서 비효율적입니다.
- 복잡도는 입력이 커질 때 작업량·메모리가 얼마나 늘어나는지 나타냅니다. n은 참가자 수입니다.
- 일반적인 해시 구현 기준 객체·Map 집계는 평균 시간 `O(n)`, 추가 공간 `O(n)`입니다. 정렬 풀이는 통상 시간 `O(n log n)`이며 복사 배열에 `O(n)` 공간이 필요합니다. 정렬 내부의 시간·공간은 엔진 구현에 따라 달라집니다.


### 알고리즘 복잡도
알고리즘 복잡도
- 시간 복잡도: 입력이 늘어날 때 작업량이 얼마나 증가하는지 나타냅니다.
- 공간 복잡도: 입력이 늘어날 때 필요한 메모리가 얼마나 증가하는지 나타냅니다.
- 빅오 표기법(Big O): 증가 정도를 O(n), O(n²)처럼 표현합니다. 실제 실행 시간이나 초 단위가 아닙니다.
- n: 입력 데이터 개수입니다. 이 문제에서는 참가자 수입니다.
- O(1): 입력 크기와 관계없이 작업량이 일정합니다. 예: arr[0] 조회.
- O(log n): 처리할 범위를 반복해서 줄입니다. 예: 이진 탐색으로 1,024개를 절반씩 줄이면 약 10단계입니다.
- O(n): 입력이 2배면 작업량도 대략 2배입니다. 예: 배열 전체를 한 번 순회.
- O(n log n): n × log n에 비례해 작업량이 증가합니다. 일반적인 효율적 정렬이 해당합니다.
- O(n²): 입력이 2배면 작업량은 대략 4배입니다. 예: 참가자마다 완주자 전체를 다시 검색.
- 작업량 증가 순서: 일반적으로 O(1) < O(log n) < O(n) < O(n log n) < O(n²)입니다.
- 반복문 분석: n번 도는 반복문 두 개를 순서대로 실행하면 2n → O(n), 중첩해서 각각 n번 돌면 n × n → O(n²)입니다.
- 메서드 내부 작업도 포함: 반복문 안의 indexOf()·filter() 등도 배열을 탐색하므로 코드가 한 줄이라고 O(1)은 아닙니다.
- 추가 공간: 입력으로 받은 데이터 외에 풀이하면서 새로 사용하는 메모리입니다.
- 추가 공간 O(1): 입력이 늘어도 추가로 저장하는 데이터 크기가 일정합니다.
- 추가 공간 O(n): 입력 개수에 비례하는 데이터를 추가 저장합니다. 예: [...participant]로 배열 복사.
- Map의 저장 공간: 서로 다른 이름이 u개면 O(u)입니다. 이름이 모두 다르면 O(n), 모두 같으면 항목 하나만 저장합니다.
- 평균 시간 복잡도: 입력이나 자료구조 동작에 대한 가정 아래 평균적인 작업량을 분석한 것입니다.
- 최악 시간 복잡도: 가장 불리한 경우의 작업량을 분석한 것입니다. 빅오가 무조건 최악만 뜻하는 것은 아닙니다.
- 통상: 공식 복잡도 용어가 아니라 ‘일반적으로’라는 뜻입니다.


### 배열 메서드 정리

- includes(값) : 해당 값이 있는지 확인 → true / false
  - 예시: ['kim', 'lee'].includes('kim') → true

- some(조건) : 조건을 만족하는 원소가 하나라도 있는지 확인 → true / false
  - 예시: [1, 2, 3].some(n => n > 2) → true

- every(조건) : 모든 원소가 조건을 만족하는지 확인 → true / false
  - 예시: [1, 2, 3].every(n => n > 2) → false

- find(조건) : 조건을 만족하는 첫 원소 반환 → 없으면 undefined
  - 예시: [1, 2, 3].find(n => n > 1) → 2

- findIndex(조건) : 조건을 만족하는 첫 원소의 인덱스 반환 → 없으면 -1
  - 예시: [1, 2, 3].findIndex(n => n > 1) → 1

- indexOf(값) : 해당 값의 첫 인덱스 반환 → 없으면 -1
  - 예시: ['kim', 'lee'].indexOf('lee') → 1

- filter(조건) : 조건에 맞는 원소만 남긴 새 배열 반환
  - 예시: [1, 2, 3].filter(n => n > 1) → [2, 3]

- map(변환) : 각 원소를 변환한 새 배열 반환
  - 예시: [1, 2, 3].map(n => n * 2) → [2, 4, 6]

- forEach(실행) : 원소마다 작업 실행 → 반환값은 undefined
  - 예시: [1, 2, 3].forEach(n => {console.log(n);}) → 콘솔에 1, 2, 3을 각각 출력

- reduce(누적 함수, 초깃값) : 원소를 누적해 최종 결과 반환
  - 예시: [1, 2, 3].reduce((sum, n) => sum + n, 0) → 6
